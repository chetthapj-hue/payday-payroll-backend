# พนักงานลงเวลาและรายได้สะสม

## วิธีเปิดใช้งาน

ใช้ระบบบัญชี/session เดิม ไม่เพิ่ม schema หรือ migration ใหม่ในงานนี้ ถ้าติดตั้ง MVP รุ่นล่าสุดแล้วให้รีสตาร์ต Backend และเปิด Frontend ตามปกติ:

```sh
cd ~/Developer/payday-payroll/server
npm start
# อีก terminal
cd ~/Developer/payday-payroll-frontend
npm run dev -- --host 127.0.0.1
```

พนักงานต้องมีบัญชีที่เปิดใช้งานและเปลี่ยนรหัสชั่วคราวแล้วตาม AUTH.md

## ลองผ่านหน้าเว็บ

1. ล็อกอินประเภท **พนักงาน** → **ลงเวลาทำงาน** วันที่เริ่มต้นเป็นวันนี้ตาม Asia/Bangkok เลือกย้อนหลังได้ ห้ามเลือกอนาคต ไม่มีช่องเลือกพนักงาน
2. เวลาปกติล็อก 8 ชม. เลือกกะ กรอก OT รวมและ OT 3 เท่าเป็นชั่วโมง เช่น 2 และ 0.5 ชั่วโมง OT 3 เป็นส่วนหนึ่งของ OT รวม ค่าชั่วโมงปัดเป็นนาทีเต็มก่อนส่ง API
3. กด **บันทึกเวลาของฉัน** ประวัติและยอดสะสมโหลดใหม่ทันทีโดยไม่ต้องรีเฟรช และเลือกงวดตามรอบค่าจ้างของวันที่เพิ่งบันทึก
4. ดูยอดใต้ฟอร์มหรือเมนู **รายได้สะสมของฉัน** เลือกเดือนจ่าย ตรวจช่วงค่าจ้าง ช่วง OT จำนวนวันที่ลงงาน และยอดรายองค์ประกอบ มีป้าย **ยอดสะสมก่อนปิดงวด**
5. เปิด **ประวัติการทำงาน** จะเลือกเดือนของวันที่เพิ่งลงเวลาไว้ให้แล้ว
6. ยอดจริงย้อนหลังเปิดจาก **เงินเดือนของฉัน** เหมือนเดิม อ่านเฉพาะ snapshot ที่บันทึกและเผยแพร่แล้ว ไม่เปลี่ยนตามการลงเวลาเพิ่ม

## สูตรและช่วงงวด

`payroll.js` export ฟังก์ชัน calculate เพียงชุดเดียวให้ Admin preview/save และ API ยอดสะสมใช้ร่วมกัน คำนวณ PostgreSQL numeric และปัด OT สองตำแหน่งตามเดิม กรอง employee_id ใน SQL ทุกส่วนรวม validation เพื่อไม่เปิดเผยหรืออ่านข้อมูลพนักงานอื่น

- ค่าจ้าง/อาหาร/กะ: 17 เดือนก่อน–16 เดือนจ่าย รวมทั้งสองวัน จำนวนวันที่ลงงานนับในช่วงนี้
- OT: 1–วันสุดท้ายเดือนก่อน จ่ายพร้อมงวดวันที่ 25 เดือนจ่าย
- งวด 25 ธันวาคม 2569: ค่าจ้าง 17 พฤศจิกายน–16 ธันวาคม 2569, OT 1–30 พฤศจิกายน 2569
- OT เดือนธันวาคมเข้ารอบ 25 มกราคม 2570 (แยกจาก OT เดือนพฤศจิกายนในงวดธันวาคม)
- รายวัน: อัตรา × จำนวนวันที่ลงงานเต็ม 480 นาที รายเดือน: **เต็มอัตราตามสูตร Admin เดิม** ไม่คำนวณเฉลี่ยตามจำนวนวันที่ลงงาน มีข้อความกำกับบนหน้าสะสม
- OT 1.5 ใช้ OT รวมลบ OT 3 และ OT 3 ใช้นาที OT 3 อัตราต่อชั่วโมงรายวัน ÷8 หรือรายเดือน ÷30÷8
- อาหารใช้ SUM meal_allowance ในช่วงค่าจ้าง ซึ่งเก็บ 83 หรือ 166 บาทตามเกณฑ์ OT >=60 นาทีแล้ว ไม่บวกเพิ่มซ้ำ กะกลางคืน 150 บาทตามเดิม
- ยอดสะสมอ่านจากรายการที่บันทึกแล้ว เป็นข้อมูลสดตามเดือนที่เลือก ไม่ได้บันทึกทับ payroll_items แม้งวดที่เลือกเผยแพร่แล้ว ส่วนหน้าเงินเดือนจริงอ่าน snapshot ตามเดิม

## API และสิทธิ์

- POST /api/me/work-logs: employee ที่เปลี่ยนรหัสแล้วเท่านั้น Backend กำหนด employee_id จาก session แม้ body ส่ง employee_id ของคนอื่นก็ไม่เปลี่ยนเจ้าของ
- GET /api/me/accrued-income?month=2026-12: คืน period, row (ของเจ้าของ session คนเดียว), as_of_date และ kind=accrued; row มี recorded_days และยอดแต่ละองค์ประกอบ
- GET /api/me/work-logs?month=YYYY-MM และ GET /api/me/payroll เดิมยังทำงานเหมือนเดิม
- ทุก POST ใช้ CSRF/session cookie เดิม ห้ามบัญชีปิดสถานะหรือยังไม่เปลี่ยนรหัสชั่วคราว

รูปแบบ POST เป็นนาทีตาม API เดิม:

```json
{
  "work_date": "2026-11-12",
  "regular_minutes": 480,
  "overtime_minutes": 120,
  "overtime_3x_minutes": 30,
  "shift_type": "night"
}
```

`work-logs.js` เป็นบริการ validation และ insert ร่วมกับ Admin แต่เส้นทางพนักงานส่ง latestDate จาก bangkokToday ฝั่ง Backend จึงห้ามวันอนาคตแม้ bypass ฟอร์ม/ปลอมวันที่ปัจจุบันใน body; Admin คงพฤติกรรม API เดิม รวมถึงการเตรียมข้อมูลทดสอบงวดอนาคต

กันซ้ำด้วย UNIQUE(employee_id,work_date) เดิมในฐานข้อมูล แม้ Admin/employee ส่งพร้อมกัน ได้หนึ่ง 201 และหนึ่ง 409 WORK_LOG_DUPLICATE ไม่ใช้การตรวจ exists ล่วงหน้าที่หลุด race ได้

## ทดสอบ

ใช้ TEST_DATABASE_URL ชื่อ payday*_test* ตาม AUTH.md แล้วรัน `npm test` ทดสอบ Backend 28 รายการ รวม:

- วันไทยก่อน/หลัง 17:00 UTC
- ลงวันนี้และย้อนหลังได้ วันพรุ่งนี้ปฏิเสธ ปลอมเจ้าของไม่สำเร็จ OT ผิด/ลงซ้ำถูกปฏิเสธ
- Admin/employee ลงวันเดียวกันพร้อมกัน เหลือแถวเดียว
- วัน 16/17, OT สิ้นเดือน/วัน 1, ธันวาคม–มกราคม
- 5 วัน × 500 = 2,500 + OT เดือนก่อน 600 = 3,100 ก่อนอาหาร/กะ
- ยอดสดเพิ่มหลังลงงาน แต่ snapshot เผยแพร่แล้วเท่าเดิม
- รายเดือนยังเต็มอัตรา และ validation งานกำกวมของคนอื่นไม่บล็อก/เปิดเผยให้เจ้าของบัญชีนี้

Chrome ผ่าน runner เดิม `tests/run-browser-tests.js` เพิ่มชุด `self-service-browser.mjs` เป็นชุดที่สี่ ทดสอบลงวันนี้/ย้อนหลังผ่านฟอร์มจริง ตรวจ payload ชั่วโมง→นาที, max date/future API, ยอดอัปเดตโดยไม่ reload, ตัวอย่าง 2,500+600 และเปิด snapshot เดิม ภาพตัวอย่าง `/tmp/payday-browser/self-service.png` เป็นข้อมูลจำลองทั้งหมด

Fixtures งวดธันวาคมในชุดทดสอบลงด้วย API Admin ในฐานทดสอบเท่านั้น เพราะช่วงตัวอย่างอาจยังอยู่ในอนาคต ณ วันรันทดสอบ ไม่มีการผ่อนเงื่อนไขวันอนาคตของ API พนักงาน
